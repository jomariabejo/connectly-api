# Agentic SDLC Architecture

This repository follows an **Agentic SDLC (Software Development Life Cycle)** approach where agents collaborate across the entire software lifecycle.

Agents are not isolated assistants — they operate as coordinated specialists with:
- Defined responsibilities
- Explicit workflow ownership
- Cross-agent review loops
- Structured handoffs
- Deterministic orchestration patterns

## Core Principle

**Skills provide capabilities.**
**Agents orchestrate execution.**
**Workflows coordinate collaboration.**

### Layered Architecture

| Layer | Responsibility |
|---|---|
| Skills | Reusable tools, references, templates, automations |
| Agents | Specialized orchestration and decision-making |
| Workflows | Multi-agent SDLC coordination |
| Projects | Real-world execution context |

# Agent Collaboration Model

## Multi-Agent Workflow Rules

Agents MUST collaborate through structured handoffs.

### Standard SDLC Flow

```text
Product Manager
    ↓
Business / Product Analysis
    ↓
Solutions Architect
    ↓
UI/UX + Engineering
    ↓
QA + Security Review
    ↓
DevOps / Deployment
    ↓
Monitoring / Feedback
```

### Collaboration Rules

1. Agents MUST review upstream outputs before execution
2. Engineering agents MUST NOT implement without requirements
3. QA agents validate against acceptance criteria
4. Security review required before production release
5. DevOps validates deployment readiness
6. SRE validates observability and reliability
7. Product agents validate business objectives post-release

# Agent Architecture

## What are cs-* Agents?

**cs-* agents** are specialized Claude Code agents that orchestrate the 177 existing skills.

Each agent:
- References skills via relative paths (`../../marketing-skill/`)
- Executes Python automation tools from skill packages
- Follows established workflows and templates
- Maintains skill portability and independence
- Participates in agentic SDLC orchestration

## Key Principle

Agents ORCHESTRATE skills.
Skills remain self-contained and portable.

Agents should:
- Delegate specialized execution to skills
- Coordinate workflows between agents
- Validate outputs before handoff
- Maintain deterministic execution patterns

# Required YAML Frontmatter

Every agent file MUST include:

```yaml
---
name: cs-agent-name
description: One-line description
skills: skill-folder-name
domain: domain-name
model: sonnet
tools: [Read, Write, Bash, Grep, Glob]
orchestration: true
handoff_support: true
review_required: true
---
```

## Additional Agentic Fields

| Field | Purpose |
|---|---|
| orchestration | Enables multi-agent coordination |
| handoff_support | Allows structured workflow delegation |
| review_required | Requires output validation before completion |

# Relative Path Resolution

All skill references MUST use:

```text
../../
```

Example:

```bash
python ../../engineering-team/backend-engineer/scripts/api_scaffold.py
```

Never hardcode absolute paths.
